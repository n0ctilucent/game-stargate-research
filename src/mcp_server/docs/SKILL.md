# RSA / IDA

This skill preserves the user's prompt systems substantially in their own form.

Use this skill when the user wants:
- `RSA: analyze`
- `RSA: distill`
- `RSA: amplify`
- `RSA: IDA`
- central-attractor finding
- structurally evasive phenomenon detection
- recursive distillation / amplification
- a clarified, stronger English articulation produced through recursive structured passes

## Operating Rule

`RSA` is the meditation engine.

`IDA` is the operant metaprompt.

That means:
- The RSA process is actually performed in the formal style indicated by the prompt.
- IDA is the recursive finishing discipline:
  - run one or more full RSA-chain passes
  - recursively distill and amplify
  - preserve the attractor and meta-carry
  - return only the final strengthened English output unless the user explicitly asks for RSA notation

Default behavior:
- If the user says `RSA: analyze`, `RSA: distill`, or `RSA: amplify`, return the requested RSA-style output.
- If the user says `RSA: IDA`, or clearly wants the polished result, perform 2-4 recursive passes internally and return only the final clarified English articulation.

## IDA Protocol

IDA means Iterative Distillation and Amplification.

When doing IDA:
1. Apply System1 exactly as a real structural pass.
2. Continue the replay using System2, then System3, then System4.
3. Distill what matters.
4. Amplify what is structurally central.
5. Repeat the cycle 2-4 times when the material benefits from recursion.
6. Preserve the central attractor.
7. Preserve the distinction between:
   - foundational semantics
   - boltable stream transforms
8. Return only the final English output, stronger and clearer than the source.

Do not expose all intermediate passes unless the user asks to see them.
